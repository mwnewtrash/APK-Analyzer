# APK Analyzer — Build Instructions

Client-side Android APK / decompiled-source vulnerability analyzer.
Runs entirely in the browser — no upload, no backend.

- **Repo root:** `D:\Notes_Excel\Projects_Claude\APK Analyzer\Analyzer_APK`
- **Stack:** Vite 7 + native ES modules, plain JavaScript (no framework), Tailwind (CDN), JSZip, sql.js
- **License:** MIT · `private: true` (not published to npm)

## 1. Prerequisites

| Requirement | Version | Notes |
|---|---|---|
| Node.js | `^20.19.0` or `>=22.12.0` | Enforced by Vite 7 (`engines` field). Validated with **v24.13.0**. |
| npm | 10+ | Validated with **11.5.2**. |

> `$LASTEXITCODE` instead of relying on the visual output:
> ```powershell
> cmd /c "npm run build > build.log 2>&1"; $LASTEXITCODE
> ```

## 4. Project layout & the code-generation pipeline

This project has a **dual-source structure** — understand this before editing anything:

```
src-legacy/           ← Legacy single-file app (upstream source of truth)
    head.html         ← Full HTML shell: <head> + <body> markup + inline CSS (167 kB)
    code.js           ← Original monolithic inline script (236 kB)
    body.html / foot.html
        │
        │  npm run regen
        │    ├─ tools/build.mjs      codemod: parses code.js with Acorn,
        │    │                        slices it into ES modules under src/
        │    │                        (applies known patches on the fly)
        │    └─ tools/make-index.cjs writes root index.html
        │                           = head.html + <script type="module" src="/src/main.js">
        ▼
src/                  ← Modular application source (mostly GENERATED, see below)
    main.js           ← ⚠️ HAND-MAINTAINED — imports every module, exposes
    │                    legacy inline-handler names on window, runs init.
    core/   engine/   ingest/   ui/   workers/
        │
        │  npm run build  (Vite)
        ▼
dist/                 ← Deployable static site (git-ignored)
```

### What is safe to edit?

| Path | Editable? | Notes |
|---|---|---|
| `src/main.js` | ✅ Hand-maintained | Never regenerated. |
| `src/core/axml.js`, `checkpoint.js`, `idb.js`, `patterns-async.js`, `state.js` | ✅ Hand-maintained / hand-patched | Not produced by the codemod (or heavily patched). |
| Most other `src/**` files | ⚠️ Generated by `tools/build.mjs` | Changes are **overwritten** by `npm run regen`. To change these permanently, edit `src-legacy/code.js` (or the patch logic in `tools/build.mjs`), then re-run `regen`. |
| `index.html` (repo root) | ⚠️ Generated | Do not edit directly — edit `src-legacy/head.html` instead. |
| `src-legacy/*` | ✅ Source of truth | Head/code of the legacy single-file build. |
| `tools/**` | ✅ | Build codemod, verifiers, and test harnesses. |
| `vite.config.js`, `package.json` | ✅ | Standard Vite config (`base: './'`, `outDir: 'dist'`, `emptyOutDir: true`). |

### When to run `regen`

Only needed when you modify `src-legacy/code.js`, `src-legacy/head.html`, or
the patch logic in `tools/build.mjs`:

```powershell
npm run regen
```

This runs `node tools/build.mjs && node tools/make-index.cjs` and reports
`module coverage: assigned=… top=… missing=[]` — **`missing=[]` must stay empty**,
otherwise a top-level declaration was not assigned to a module.

> **Known drift:** as of the current commit, the checked-in `index.html` is slightly
> stale relative to `src-legacy/head.html` (two pending CSS/markup tweaks: a removed
> `translateY(-2px)` on `.nav-link` and a new scan-history note). Running
> `npm run regen` will show `index.html` as modified in `git status` — that is
> expected; review the diff and commit it. All `src/` files regenerate

## 5. Verification & tests

Run these before committing. All commands exit **0** on success.

### Static verifiers (source-level checks)

| Command | What it checks |
|---|---|
| `npm run verify` | ~40 regression assertions on `src/**` + `src-legacy/head.html`: required patches present, dead code removed, SRI hashes on CDN tags, zip-bomb guard, worker call counts, a11y/export/SPLITAPK/SQLITE checks, etc. |
| `npm run verify:freeze` | Async-import discipline: pattern/endpoints code must go through the worker path; no direct sync `dex` import. |
| `npm run verify:history` | Scan-history feature: save imports/calls, history section, JADX details, single decompiled zone. |

### Analysis metadata tools (optional / maintainer use)

- `npm run map -- <html-file>` — Acorn-based top-level declaration map (`tools/declmap.js`).
- Root `xref.json`, `declmap.json`, `graph.json`, `inventory.json`, `purity.json`,
  `scope.json` — cached code-analysis artifacts consumed by `tools/build.mjs`
  (notably `xref.json` supplies the mutable-global set used by the codemod).
  Regenerate with the corresponding `tools/*.cjs` scripts when refactoring.
- `audit-loading.cjs` is a one-off diagnostic that dumps loading-section markup
  from `head.html`.

## 6. Deployment

`dist/` is a **fully static site** — host it on any static file server
(GitHub Pages, Netlify, S3, nginx, or a local folder):

- `vite.config.js` sets `base: './'`, so it works from any sub-path
  (no domain-root requirement).
- `dist/` is git-ignored; deploy from a fresh `npm run build`, not from the repo.

**Runtime CDN dependencies** (loaded from `index.html` with Subresource Integrity):

| Resource | Source | Failure impact |
|---|---|---|
| Tailwind CSS browser build 4.3.3 | jsdelivr | Styling breaks. |
| JSZip 3.10.1 | cdnjs | APK (zip) ingestion breaks. |
| Inter / Montserrat / JetBrains Mono fonts | fonts.googleapis.com | Fallback fonts only. |

For fully offline/intranet deployments, vendor these three locally and update the
tags in `src-legacy/head.html` (then `npm run regen`), keeping valid `integrity`
attributes — `npm run verify` asserts that SRI hashes are present.

**Client-side storage:** scan results persist in IndexedDB (reload-safe).
Serve over `http://localhost` or HTTPS; do not open `dist/index.html` via `file://`
(workers, WASM, and module scripts require an HTTP origin).

## 7. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `npm run dev`/`build` fails with engine error | Node < 20.19 or 22.12 → upgrade Node (`node --version`). |
| PowerShell reports exit code 1 with `NativeCommandError` on a successful build | stderr warning noise; check the log for `✓ built` instead (see §1 tip). |
| Edits to a `src/**` file disappear after `npm run regen` | That file is codemod-generated — edit `src-legacy/code.js` or the patches in `tools/build.mjs` (see §4). |
| `index.html` shows as modified right after `regen` | Expected: committed `index.html` was stale vs `head.html`. Review & commit (see §4 note). |
| `module coverage: … missing=[name]` from `regen` | A new top-level declaration in `code.js` wasn't assigned to a module — extend the module map in `tools/build.mjs`. |
| `verify` FAIL on `WORKER-FILES` | `dist/` is missing/stale (hashed worker filename changed). Run `npm run build` first. |
| App can't parse an APK / SQL features missing | Ensure `dist/assets/sql-wasm-*.wasm` was emitted and is served with the site (do not deploy `index.html` alone). |
| `indexedDB is not defined` in `test:history`/`test:resume` | Expected in Node (see §5 footnote) — not a failure. |
| `devserver.log` in repo root | Old dev-server log; git-ignored (`*.log`), safe to delete. |
